3) Silver Layer (Cleaning)
models/silver/stg_customers.sql

{{ config(
    materialized='incremental',
    unique_key='customer_id'
) }}

select
    customer_id,
    trim(name) as name,
    lower(email) as email,
    city,
    created_at
from {{ source('bronze', 'customers_raw') }}
where name is not null

{% if is_incremental() %}
  and created_at >= dateadd(day, -2, (select max(created_at) from {{ this }}))
{% endif %}


models/silver/stg_orders.sql

{{ config(
    materialized='incremental',
    unique_key='order_id',
    incremental_strategy='merge'
) }}

select
    order_id,
    customer_id,
    amount,
    status,
    order_date
from {{ source('bronze', 'orders_raw') }}

{# runs only if incremental, and looks for orders within the last two days of max order date=#}

{% if is_incremental() %}
  and order_date >= dateadd(day, -2, (select max(order_date) from {{ this }}))
{% endif %}

4) Gold Layer (Business Models)
models/gold/fct_orders.sql
select
    o.order_id,
    o.customer_id,
    c.name,
    o.amount,
    o.order_date
from {{ ref('stg_orders') }} o
join {{ ref('stg_customers') }} c
    on o.customer_id = c.customer_id
	
models/gold/customer_revenue.sql
select
    customer_id,
    sum(amount) as total_revenue
from {{ ref('fct_orders') }}
group by customer_id

5) Tests:: dbt tests return bad data, not good data
👉 You are not writing tests directly
👉 You are telling dbt to generate SQL queries automatically

version: 2

models:
  - name: stg_customers
    columns:
      - name: customer_id
        tests:
          - not_null
          - unique

  - name: stg_orders
    columns:
      - name: order_id
        tests:
          - not_null
          - unique
		  
👉 If this returns ANY rows → test FAILS
👉 If 0 rows → PASS		

Relationship test (real-world useful)

If you add:

- name: stg_orders
  columns:
    - name: customer_id
      tests:
        - relationships:
            to: ref('stg_customers')
            field: customer_id

dbt runs:

select customer_id
from stg_orders
where customer_id not in (
    select customer_id from stg_customers
)

👉 Ensures:
Every order has a valid customer

🧠 Why this is powerful

You’re basically adding:

Data validation
Data integrity
Production safety

👉 Without writing full SQL manually

🔥 Real-world usage

Companies use dbt tests to:

Catch bad data early
Prevent broken dashboards
Enforce data contracts
